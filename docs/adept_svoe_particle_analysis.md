# ADEPT Particle-Count Analysis

## Purpose

This analysis measures how ADEPT's particle count affects:

- physical-reasoning runtime;
- run-to-run stability on ordinary control videos;
- agreement with the released 128-particle configuration;
- calibrated Shannon Violation of Expectation (SVoE) traces.

ADEPT's core code remains unchanged. The experiment runner imports ADEPT's
existing particle filter, and the analysis operates only on saved JSON results
and timing records.

## Reproducible inputs

Each particle-count experiment writes a manifest:

```text
output/<experiment>/manifest.json
```

Every manifest identifies the exact result and timing files for each
particle-count, replicate, and case combination. The analysis configuration is:

```text
experiments/svoe_particle_analysis.yaml
```

It lists all manifests explicitly, names the ordinary control cases used for
calibration, and identifies 128 particles as the comparison baseline.

The current design uses two 170-frame control cases and five stochastic
replicates per particle count:

```text
human_block_0051_0
human_disappear_0007_3
```

These two cases are sufficient for implementation, timing, and exploratory
stability work. They are not sufficient for final estimates of failure
probability or control-versus-violation discrimination.

## Running the analysis

After all manifests listed in the YAML file exist, run from the repository
root:

```bash
python -m svoe_calibration.analyze_particles \
  --config experiments/svoe_particle_analysis.yaml
```

The analysis runs under the `adept-model` Conda environment and does not need
Apptainer because it reads saved outputs rather than invoking ADEPT physics.

## Validation performed while loading

The loader rejects:

- missing manifest fields;
- duplicate particle-count/replicate/case combinations;
- missing case or score fields;
- empty or non-finite score arrays;
- disagreement between recorded and observed frame counts;
- non-positive or non-finite elapsed times.

This prevents incomplete or accidentally duplicated runs from silently entering
the comparison.

## Run summaries

For every run, the analysis records:

- minimum, mean, and maximum ADEPT score;
- minimum, mean, and maximum SVoE bits;
- elapsed physical-reasoning time;
- seconds per frame;
- source result and timing paths.

For every particle-count and case group, it reports:

- mean and sample standard deviation of replicate means;
- mean and sample standard deviation of replicate maxima;
- mean, 95th percentile, and maximum of the framewise sample standard
  deviations;
- mean and sample standard deviation of runtime.

All reported standard deviations use the sample definition with denominator
`n - 1`. Shaded plot bands show the framewise mean plus or minus one sample
standard deviation, clipped at zero because both ADEPT and SVoE scores are
non-negative.

## Agreement with the 128-particle baseline

For each case, replicate traces are averaged separately at every particle
count. The mean trace is compared with the corresponding 128-particle mean
trace using:

- Pearson correlation;
- mean absolute difference (MAD);
- root mean square difference (RMSD).

The same measures are also computed for every individual replicate against the
128-particle mean. Individual comparisons expose stochastic failures that an
aggregate mean could conceal.

## Leave-one-replicate-out SVoE

Each particle count is calibrated against controls generated by that same
particle count. For target replicate `r`, the reference contains all frames
from the named control cases in every replicate except `r`.

With five replicates, two control cases, and 170 frames per case, each fold has:

```text
4 replicates x 2 cases x 170 frames = 1360 reference scores
```

For target ADEPT score `c`, let `k` be the number of reference scores greater
than or equal to `c`, and let `n` be the reference count. The add-one empirical
tail probability and SVoE are:

```text
p = (k + 1) / (n + 1)
SVoE = -log2(p)
```

The maximum resolvable value for a 1360-score fold is:

```text
log2(1361) = 10.4104513515 bits
```

Leaving out the entire target replicate prevents its ordinary frames from
calibrating themselves. Pooling both control scenarios gives a broader ordinary
reference than either case alone.

If future experiments use different replicate counts, their empirical
resolution will differ. Final cross-model comparisons should therefore use
equal-sized, explicitly defined calibration sets.

## Output files

The default output folder is:

```text
output/svoe_particle_analysis/
```

The command writes:

| File | Contents |
|---|---|
| `analysis.json` | Complete machine-readable report and provenance |
| `run_summary.csv` | ADEPT, SVoE, and timing summary for every run |
| `aggregate_summary.csv` | ADEPT stability, runtime, and speedup by group |
| `svoe_aggregate_summary.csv` | SVoE stability by group |
| `adept_group_comparison.csv` | Mean ADEPT traces versus N=128 |
| `svoe_group_comparison.csv` | Mean SVoE traces versus N=128 |
| `adept_run_comparison.csv` | Every replicate versus the N=128 mean |
| `top_frames.csv` | Highest-scoring frames in every run |
| `svoe_frames.csv` | Frame-level ADEPT scores, probabilities, and bits |

The `figures/` tree contains:

- every replicate trace for every particle count and case;
- mean ADEPT and SVoE traces against N=128, with sample-standard-deviation
  bands;
- the runtime-versus-particle-count curve.

## Validation

Run the complete test suite with:

```bash
python -m unittest discover -s tests
```

The analysis tests cover manifest loading, frame-count validation, framewise
sample standard deviation, trace comparison, leave-one-replicate-out reference
construction, runtime normalization, highest-frame selection, particle-level
inspection, and figure generation. A separate end-to-end smoke test verifies
that a synthetic multi-particle experiment produces the documented JSON, CSV,
and PNG outputs.

## Particle-level anomaly inspection

Selected frames can be inspected without an ad hoc Python snippet:

```bash
python -m svoe_calibration.inspect_particles \
  --result output/svoe_particles_016/particles_016/replicate_004/human_disappear_0007_3/result.json \
  --frames 140 141 142 143 144 \
  --output output/svoe_particle_analysis/n016_replicate004_frames_140_144.json
```

The report includes the aggregate ADEPT score, per-particle raw scores, and the
number and coordinates of retained non-occluder object beliefs.

## Preliminary exploratory findings

The following observations were made during interactive inspection. They are
not yet formal estimates of failure probability:

- One particle is fast but produces grossly unstable trajectories.
- At 16 particles, one disappearance replicate collapsed around frame 142; all
  particle residuals rose together before the non-occluder beliefs vanished.
- At 24 particles, two disappearance replicates retained elevated trajectories
  for an extended interval.
- At 28 particles, one disappearance replicate diverged from approximately
  frames 97 through 142.
- At 30 particles, four disappearance replicates were elevated and one reached
  an ADEPT score above 157 near frame 142.
- Five initial 32-particle replicates closely followed the 128-particle mean,
  but five successes do not establish a failure-free threshold.
- Five 128-particle replicates were stable on the two available controls.

Because ADEPT deliberately injects operating-system randomness during particle
evolution, apparent reliability need not be monotonic in small replicate
samples. The particle-count search is therefore an efficient exploratory
design, not a deterministic binary search. The next test at 48 particles checks
whether reliability becomes visibly more robust above the unstable region.

## Adaptive execution concept

The observed failures suggest a possible future design:

1. Run ADEPT with a reduced particle count.
2. Convert its control-calibrated score to SVoE bits.
3. Treat an extreme SVoE event as a computational alarm.
4. Restore an earlier checkpoint and rerun the interval with more particles.
5. If the surprise disappears, classify the first event as particle depletion;
   if it persists, retain it as evidence of a possible physical violation.

SVoE would trigger escalation; it would not reconstruct hypotheses that the
reduced particle filter had already discarded. This design remains a proposal
for later testing.

## Required next stage

The current controls establish runtime and stochastic stability only. The
central scientific comparison requires matched ordinary and violation videos.
Each particle-count model must be calibrated against its own ordinary controls,
then evaluated on the same held-out violation set. The final selection must
balance runtime against preservation of control-versus-violation separation.
